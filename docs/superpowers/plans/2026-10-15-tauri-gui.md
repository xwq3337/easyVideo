# Tauri GUI 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把桌面界面从 egui 换成 Tauri + React，界面能力与 egui 版严格对等，core 的既有行为一行不改。

**Architecture:** core（`src/core/**`）作为 lib crate 原样复用，`src-tauri/` 是新的 Tauri 应用 crate，`ui/` 是 Vite + React + TypeScript + Tailwind 前端。core 的 tokio broadcast 事件由 `src-tauri` 里一个常驻任务搬到前端；前端一个纯 reducer 消费事件，收到 `engine://resync` 时用 `get_tasks` 整体重取。

**Tech Stack:** Rust 1.77+ / Tauri v2 / tokio（core 既有）/ React 19 + TypeScript 5 + Vite 6 + Tailwind CSS v4 / vitest

**Spec:** `docs/superpowers/specs/2026-10-15-tauri-gui-design.md`（本计划由它推导；执行者两份都要读）

## Global Constraints

- **功能对等，不加新功能。** 界面能力逐条对应 egui 版；不补"界面内看日志"，不做安装包/签名/多语言。
- **core 的既有代码零改动。** 唯一允许的改动是新公开方法 `Engine::pending_choice(id)`。core **不引入 serde**——wire DTO 只在 `src-tauri/src/dto.rs`。
- **根目录 `cargo test` 只跑 core，且必须全绿。** 改造前 78 passed；删掉 `tests/ui_font_test.rs` 后**应为 77 passed**。这个数字在计划结束时必须对得上。
- **界面语言是中文**，文案沿用 egui 版（`下载` / `暂停` / `继续` / `重试` / `删除` / `设置` / `选择格式` / `总速度` 等）。
- **不引状态库**（不用 redux/zustand/jotai）；**不引粘贴板插件**（用 WebView 原生 paste 事件）。
- **不做本地乐观更新**：用户操作后等 core 的事件回来再改界面。
- **视觉**：浅色极简 + 深色版，跟随系统且设置里可强制；无边框窗口，工具条与标题栏合一。
- **代码块是草图，不是编译过的代码。** 本计划里的 Rust/TS 片段按当时的 API 记忆写成；以编译器与真实 crate 的 API 为准。**若你看到的签名与计划不符，按实际的改，并如实报告，不要为了迁就计划而改坏实现。**

## Review Focus

以下是规格隐含、但任何任务的自动测试都覆盖不到、最可能咬到真实使用者的五类情况。每条都在下文对应任务里配了测试或验收项：

1. **广播通道 `Lagged` 之后，停在 `AwaitingChoice` 的任务能否重新拿到候选列表。** 期望：重同步后模态框能重新打开，任务可继续；不能出现"任务在列表里但没有任何按钮可点"。→ Task 7 的 reducer 测试 + Task 11 的补齐路径。
2. **`add_url` 返回 id 之前，core 已经在发这个任务的事件。** 期望：未知 id 不丢帧、不报错，而是触发一次重同步把该行补上。→ Task 7。
3. **任务跑动中改下载目录，再删除该任务。** 期望：清理删的是它**实际写入**的目录，不误删新目录里同号的 `task-<id>`（core 上一轮刚修的不变量，GUI 不得绕过）。→ Task 12 验收项。
4. **`titleBarStyle: Overlay` 下红绿灯与工具条输入框重叠。** 期望：左侧留出安全边距，输入框不被压住。这与 egui 版"输入框把按钮挤出裁剪区、设置窗口因此打不开"是同一族缺陷。→ Task 8 步骤 5 的真实窗口检查。
5. **无边框窗口在 Windows/Linux 上的自绘按钮与拖拽区。** 期望：最小化/最大化/关闭可用，拖拽区不吞掉输入框内的文字选择。本机（macOS）验证不到，必须明确标注为未验证。→ Task 8 与 Task 12。

- [ ] **Step 8: `src-tauri/src/main.rs`（最小版，只开窗口）**

```rust
use tauri::Manager;

fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_dialog::init())
        .setup(|app| {
            // **macOS 上必须保留 decorations。** Tauri 自己的配置文档
            // (`tauri-utils` 的 config.rs，`traffic_light_position` 那一项) 写明
            // `titleBarStyle: Overlay` "Requires ... decorations: true" —— 红绿灯是那圈
            // 边框的一部分，`decorations: false` 会把它一并拿走。而界面层的 `WindowControls`
            // 在 macOS 上按设计不渲染（它指望系统红绿灯），两者叠加就是一个**没有任何
            // 关闭/最小化按钮**的窗口。
            //
            // 所以：macOS 保留 decorations（Overlay 让标题栏那一条看不见、红绿灯浮在内容上），
            // Windows/Linux 才真正去掉边框，交给自绘按钮。
            #[cfg(not(target_os = "macos"))]
            if let Some(w) = app.get_webview_window("main") {
                w.set_decorations(false).ok();
            }
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

（Tauri CLI 默认找 `src-tauri/src/main.rs`；先把空窗口跑起来，后面几个任务再往里加东西。
这个 `setup` 钩子里的东西**不要删** —— Task 6 会重写 `main.rs`，届时把它并进那一个 `setup`。）

```rust
    ///
    /// `ChoicesOffered` 是一次性事件：界面一旦错过（广播通道 `Lagged`）或者重连后本地没有副本，

    pub fn pending_choice(&self, id: TaskId) -> Option<ChoiceKind> {

            .tasks
            .lock()

            .and_then(|t| t.pending_choice.clone())
    }
```

```rust
//! core 与前端之间的 wire 类型。
//!
//! 存在的理由：**core 不引入 serde**。这一层把 core 的类型翻译成前端能直接 switch 的形状，
//! 顺带把"core 改名"和"前端契约"解耦——core 内部怎么变，只要这里补齐翻译就不影响界面。
//! 字段一律 camelCase（前端习惯），Rust 侧用 `#[serde(rename_all = "camelCase")]`。

use easydownvideo::core::engine::TaskSnapshot;
use easydownvideo::core::events::{Choice, ChoiceKind, EngineEvent, ProgressUnit, TaskState};
use easydownvideo::settings::Settings;
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug, Clone, PartialEq, Eq)]
#[serde(tag = "kind", rename_all = "camelCase")]
pub enum StateDto {
    Queued,
    Probing,
    AwaitingChoice,
    Downloading,
    Merging,
    Paused,
    Done,
    Failed { message: String },
    Canceled,
}

impl From<&TaskState> for StateDto {
    fn from(s: &TaskState) -> Self {
        match s {
            TaskState::Queued => StateDto::Queued,
            TaskState::Probing => StateDto::Probing,
            TaskState::AwaitingChoice => StateDto::AwaitingChoice,
            TaskState::Downloading => StateDto::Downloading,
            TaskState::Merging => StateDto::Merging,
            TaskState::Paused => StateDto::Paused,
            TaskState::Done => StateDto::Done,
            TaskState::Failed(m) => StateDto::Failed { message: m.clone() },
            TaskState::Canceled => StateDto::Canceled,
        }
    }
}

#[derive(Serialize, Deserialize, Debug, Clone, Copy, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub enum UnitDto {
    Bytes,
    Segments,
}

impl From<ProgressUnit> for UnitDto {
    fn from(u: ProgressUnit) -> Self {
        match u {
            ProgressUnit::Bytes => UnitDto::Bytes,
            ProgressUnit::Segments => UnitDto::Segments,
        }
    }
}

#[derive(Serialize, Debug, Clone)]
#[serde(rename_all = "camelCase")]
pub struct TaskDto {
    pub id: u64,
    pub url: String,
    pub filename: String,
    pub state: StateDto,
    pub downloaded: u64,
    pub total: u64,
    pub unit: UnitDto,
}

/// 从快照构造。`list_tasks()` 给的是**同一批** `ProgressHandle`，所以这里读到的进度
/// 与后台 worker 正在写的原子计数器是同一份，不存在快照过期的问题。
pub fn task_dto(t: TaskSnapshot) -> TaskDto {
    let (downloaded, total) = t.progress.snapshot();
    TaskDto {
        id: t.id,
        url: t.url,
        filename: t.filename,
        state: StateDto::from(&t.state),
        downloaded,
        total,
        unit: UnitDto::from(t.progress.unit()),
    }
}

#[derive(Serialize, Debug, Clone)]
#[serde(tag = "type", rename_all = "camelCase")]
pub enum EventDto {
    StateChanged { id: u64, state: StateDto },
    Progress {
        id: u64,
        downloaded: u64,
        total: u64,
        unit: UnitDto,
    },
    ChoicesOffered { id: u64, kind: ChoiceKindDto },
}

pub fn event_dto(ev: EngineEvent) -> EventDto {
    match ev {
        EngineEvent::StateChanged { id, state } => EventDto::StateChanged {
            id,
            state: StateDto::from(&state),
        },
        EngineEvent::Progress {
            id,
            downloaded,
            total,
            unit,
        } => EventDto::Progress {
            id,
            downloaded,
            total,
            unit: UnitDto::from(unit),
        },
        EngineEvent::ChoicesOffered { id, kind } => EventDto::ChoicesOffered {
            id,
            kind: ChoiceKindDto::from(kind),
        },
    }
}

#[derive(Serialize, Deserialize, Debug, Clone, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct VariantDto {
    pub uri: String,
    pub bandwidth: u64,
    pub resolution: Option<(u64, u64)>,
}

#[derive(Serialize, Deserialize, Debug, Clone, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct FormatDto {
    pub id: String,
    pub ext: String,
    pub note: String,
    pub filesize: Option<u64>,
    pub url: String,
}

/// **必须是 struct 变体，不能写成 `HlsVariants(Vec<VariantDto>)` 这样的新类型变体。**
///
/// serde 的内部标签（`tag = "kind"`）**无法序列化"带序列的新类型变体"**，运行期会报
/// `cannot serialize tagged newtype variant ChoiceKindDto::HlsVariants containing a sequence`
/// —— 编译期完全看不出来。最初那四条测试都没碰 `ChoicesOffered`，所以 RED→GREEN 一路是绿的，
/// 这个 bug 是被"把真实 JSON 打出来核对"那一步逮住的，不是被测试逮住的。
///
/// `rename_all_fields` 让内层字段也 camelCase，于是 JSON 正好是前端 sketch 要的
/// `{"kind":"hlsVariants","hlsVariants":[...]}`。
#[derive(Serialize, Deserialize, Debug, Clone, PartialEq, Eq)]
#[serde(tag = "kind", rename_all = "camelCase", rename_all_fields = "camelCase")]
pub enum ChoiceKindDto {
    HlsVariants { hls_variants: Vec<VariantDto> },
    YtdlpFormats { ytdlp_formats: Vec<FormatDto> },
}

impl From<ChoiceKind> for ChoiceKindDto {
    fn from(k: ChoiceKind) -> Self {
        match k {
            ChoiceKind::HlsVariants(v) => ChoiceKindDto::HlsVariants {
                hls_variants: v
                    .into_iter()
                    .map(|c| VariantDto {
                        uri: c.uri,
                        bandwidth: c.bandwidth,
                        resolution: c.resolution,
                    })
                    .collect(),
            },
            ChoiceKind::YtdlpFormats(f) => ChoiceKindDto::YtdlpFormats {
                ytdlp_formats: f
                    .into_iter()
                    .map(|c| FormatDto {
                        id: c.id,
                        ext: c.ext,
                        note: c.note,
                        filesize: c.filesize,
                        url: c.url,
                    })
                    .collect(),
            },
        }
    }
}

#[derive(Deserialize, Debug, Clone, PartialEq, Eq)]
#[serde(tag = "kind", rename_all = "camelCase")]
pub enum ChoiceDto {
    Variant { index: usize },
    YtdlpFormat { index: usize },
}

impl From<ChoiceDto> for Choice {
    fn from(c: ChoiceDto) -> Self {
        match c {
            ChoiceDto::Variant { index } => Choice::Variant(index),
            ChoiceDto::YtdlpFormat { index } => Choice::YtdlpFormat(index),
        }
    }
}

#[derive(Serialize, Deserialize, Debug, Clone, PartialEq)]
#[serde(rename_all = "camelCase")]
pub struct SettingsDto {
    pub download_dir: String,
    pub segment_concurrency: usize,
    pub max_active_tasks: usize,
    pub ytdlp_enabled: bool,
    pub ffmpeg_path_override: Option<String>,
}

pub fn settings_dto(s: Settings) -> SettingsDto {
    SettingsDto {
        download_dir: s.download_dir.to_string_lossy().into_owned(),
        segment_concurrency: s.segment_concurrency,
        max_active_tasks: s.max_active_tasks,
        ytdlp_enabled: s.ytdlp_enabled,
        ffmpeg_path_override: s.ffmpeg_path_override.map(|p| p.to_string_lossy().into_owned()),
    }
}

pub fn settings_from(s: SettingsDto) -> Settings {
    Settings {
        download_dir: s.download_dir.into(),
        segment_concurrency: s.segment_concurrency,
        max_active_tasks: s.max_active_tasks,
        ytdlp_enabled: s.ytdlp_enabled,
        ffmpeg_path_override: s.ffmpeg_path_override.map(Into::into),
    }
}
```

```rust
//! core → 前端的单向事件桥。
//!
//! core 用 tokio 的 broadcast 通道往外发事件：容量 256，**跟不上的时候丢的是最旧的消息**。
//! 所以这里不是"把事件转发一下就完了"——`Lagged` 必须被当成一件正事处理：
//! 明确告诉前端"你落后了 n 条，请重新拉一次全量"。
//!
//! 反面教材就在这个仓库的历史里：egui 版把 `Lagged` 与"队列空"一视同仁
//! （`while let Ok(ev) = rx.try_recv()`），于是只要 UI 线程被阻塞一次（当时是文件选择对话框），
//! 丢掉一个 `Done` 事件，那一行就**永久**停在"下载中"，只有重启才能恢复。

use std::sync::Arc;

use easydownvideo::core::events::EngineEvent;
use tokio::sync::broadcast;

use crate::dto::{event_dto, EventDto};

pub const EVENT: &str = "engine://event";
pub const RESYNC: &str = "engine://resync";

/// 桥的出口。抽成 trait 是为了让 `Lagged` 分支可测——直接依赖 `AppHandle` 的话，
/// 恰恰是最该被钉死的那条分支测不了。
pub trait EventSink: Send + Sync + 'static {
    fn emit(&self, event: &str, payload: serde_json::Value);
}

impl EventSink for tauri::AppHandle {
    fn emit(&self, event: &str, payload: serde_json::Value) {
        use tauri::Emitter;
        // **必须写全 `Emitter::emit(self, ...)`。** `AppHandle` 同时实现了本 trait 与 tauri 的
        // `Emitter`，两者都有 `emit`，裸写 `self.emit(...)` 是 E0034（multiple applicable items）。
        //
        // 发不出去（前端还没加载完）不是错误：前端水合时会用 get_tasks 补全，
        // 而任何一次状态变化之后也都会重新对账。
        let _ = Emitter::emit(self, event, payload);
    }
}

/// 把通道里**这次 `Lagged` 之前**已经发出的残余消息排空，返回一并丢掉的条数。
///
/// **不能"把剩下的转发出去就算完"** —— 那是本任务最初那版草图的写法，跑起来是红的
/// （`got.last()` 是 `engine://event` 而不是 resync）。这些消息的产生时间都早于 resync 信号，
/// 而前端收到 resync 会立刻 `get_tasks()` 整体重取；**invoke 的响应与事件走的是两条不同的
/// IPC 通道**，排在 resync 之后的旧消息完全可能晚于那份全量快照落地，用旧数据把刚拉到的
/// 正确状态盖回去。一旦被盖回去的是 `StateChanged { Done }` 这类"之后不会再有事件来纠正"
/// 的消息，那一行就永久停在错误状态 —— 正好重演这个桥存在的理由所要防的那一类缺陷。
///
/// 丢掉的信息不会真的丢：状态与进度由 `get_tasks()` 补齐，候选列表由 `pending_choice(id)` 补齐。
fn drain_stale(rx: &mut broadcast::Receiver<EngineEvent>) -> u64 {
    let mut dropped = 0;
    loop {
        match rx.try_recv() {
            Ok(_) => dropped += 1,
            Err(broadcast::error::TryRecvError::Empty) => break,
            Err(broadcast::error::TryRecvError::Closed) => break,
            // 排空过程中可能又落后一次：那些同样是被覆盖掉的消息，一并计入。
            Err(broadcast::error::TryRecvError::Lagged(n)) => dropped += n,
        }
    }
    dropped
}

pub async fn run<S: EventSink>(sink: Arc<S>, mut rx: broadcast::Receiver<EngineEvent>) {
    loop {
        match rx.recv().await {
            Ok(ev) => {
                let dto: EventDto = event_dto(ev);
                match serde_json::to_value(dto) {
                    Ok(v) => sink.emit(EVENT, v),
                    Err(e) => tracing::warn!("事件序列化失败: {e}"),
                }
            }
            Err(broadcast::error::RecvError::Lagged(n)) => {
                // 先排空、后发 resync：`dropped` 报的是前端**永远看不到**的总条数
                // （被覆盖掉的 n 条 + 排在 resync 之前、被我们主动丢弃的残余）。
                let suppressed = drain_stale(&mut rx);
                sink.emit(RESYNC, serde_json::json!({ "dropped": n + suppressed }));
            }
            // 发送端没了就结束，否则这个循环会永远空转。
            Err(broadcast::error::RecvError::Closed) => break,
        }
    }
}
```

```rust
/// core 需要一个 tokio runtime handle。**我们自己建这个 runtime**，不依赖 Tauri 内部用的是什么。
/// 它必须活得和进程一样久，所以放进 static。
static RT: OnceLock<tokio::runtime::Runtime> = OnceLock::new();

fn init_tracing(data_dir: &std::path::Path) {
    std::fs::create_dir_all(data_dir.join("logs")).ok();
    let (writer, _guard) = tracing_appender::non_blocking(tracing_appender::rolling::daily(
        data_dir.join("logs"),
        "easydownvideo.log",
    ));
    // guard 必须活到进程结束，泄漏它是有意的
    std::mem::forget(_guard);
    tracing_subscriber::fmt()
        .with_env_filter(
            tracing_subscriber::EnvFilter::try_from_default_env().unwrap_or_else(|_| "info".into()),
        )
        .with_writer(writer)
        .init();
}

fn main() {
    let data_dir: PathBuf = Settings::data_dir();
    init_tracing(&data_dir);

    let rt = RT.get_or_init(|| tokio::runtime::Runtime::new().expect("create tokio runtime"));
    let settings = Settings::load();

    let engine = easydownvideo_tauri::state::build_engine(
        rt.handle().clone(),
        settings.clone(),
        data_dir.clone(),
    );

    // 断点恢复：扫描上次未完成的任务并重新入队（与 egui 版的 main 一致）
    for m in easydownvideo::core::task::scan_resume(&settings.download_dir) {
        tracing::info!("resuming task {} ({})", m.id, m.filename);
        engine.resume(m);

}
```

```ts
import type { ChoiceKindDto, EventDto, SettingsDto, TaskView } from "../lib/types";

export interface UiState {
  tasks: TaskView[];
  settings: SettingsDto | null;
  /** 收到过无法对应到已知任务的 id。为 true 时由 store 去拉一次全量。 */
  needsResync: boolean;
  /** 上一次重同步丢了多少条（用于状态栏提示；0 表示没丢过）。 */
  lastDropped: number;
  /** 命令级失败的提示，逐条可关。 */
  toasts: string[];
}

export const initialState: UiState = {
  tasks: [],
  settings: null,
  needsResync: false,
  lastDropped: 0,
  toasts: [],
};

/** 把秒数说成人话。速度算不出来时调用方应当直接不显示，而不是显示 "剩 0 秒"。 */
export function humanizeSeconds(s: number): string {
  const total = Math.max(0, Math.round(s));
  if (total < 60) return `${total} 秒`;
  if (total < 3600) {
    const m = Math.floor(total / 60);
    const sec = total % 60;
    return sec === 0 ? `${m} 分` : `${m} 分 ${sec} 秒`;
  }
  const h = Math.floor(total / 3600);
  const m = Math.round((total % 3600) / 60);
  return m === 0 ? `${h} 小时` : `${h} 小时 ${m} 分`;
}

export type Action =
  | { kind: "hydrate"; tasks: TaskView[] }
  | { kind: "event"; event: EventDto; now?: number } // now 便于测试，默认 Date.now()
  | { kind: "choices"; id: number; choices: ChoiceKindDto }
  | { kind: "settings"; settings: SettingsDto }
  | { kind: "resyncRequested"; dropped: number }
  | { kind: "editFilename"; id: number; filename: string }
  | { kind: "setEditing"; id: number; editing: boolean }
  | { kind: "pushToast"; text: string }
  | { kind: "dismissToast"; index: number };

export function reduce(state: UiState, action: Action): UiState {
  switch (action.kind) {
    case "hydrate":
      // 整体替换，不做合并：core 是唯一真相源。
      // 本地那些只属于界面的字段（choices / editing）尽量保留，
      // 否则重同步会把用户正在输入的框清空。
      return {
        ...state,
        tasks: action.tasks.map((fresh) => {
          const old = state.tasks.find((t) => t.id === fresh.id);
          return {
            ...fresh,
            choices: old?.choices ?? null,
            editing: old?.editing ?? false,
            filename: old?.editing ? old.filename : fresh.filename,
          };
        }),
        needsResync: false,
      };

    case "resyncRequested":
      return { ...state, needsResync: true, lastDropped: action.dropped };

    case "settings":
      return { ...state, settings: action.settings };

    case "choices":
      return {
        ...state,
        tasks: state.tasks.map((t) => (t.id === action.id ? { ...t, choices: action.choices } : t)),
      };

    case "editFilename":
      return {
        ...state,
        tasks: state.tasks.map((t) => (t.id === action.id ? { ...t, filename: action.filename } : t)),
      };

    case "setEditing":
      return {
        ...state,
        tasks: state.tasks.map((t) => (t.id === action.id ? { ...t, editing: action.editing } : t)),
      };

    case "pushToast":
      return { ...state, toasts: [...state.toasts, action.text] };

    case "dismissToast":
      return { ...state, toasts: state.toasts.filter((_, i) => i !== action.index) };

    case "event":
      return applyEvent(state, action.event, action.now ?? Date.now());
  }
}

function applyEvent(state: UiState, event: EventDto, now: number): UiState {
  const known = state.tasks.some((t) => t.id === event.id);
  if (!known) {
    // 见 reducer.test.ts 里那条测试：不丢帧、不报错，记一笔去拉全量。
    return { ...state, needsResync: true };
  }
  return {
    ...state,
    // **能落到已知行上，说明又收到了一帧可应用的：把"待重同步"清掉。**
    //
    // 这一行原是计划里的缺陷：草图把 `needsResync: true` 原样带了下去，于是它**过不了计划自己
    // 写的那条测试**（"状态变化落到对应行，并清掉 needsResync"）。写代码块和写测试块时
    // 各想了一半 —— 这个仓库里记过好几回同一类（DEFECT-31/33）。
    //
    // 清它**不会取消已经在途的那次 hydrate**：store 的 dispatch 里
    // `scheduleResyncIfNeeded` 与置位发生在**同一个同步 tick**，置位后 hydrate 已经开始了。
    needsResync: false,
    tasks: state.tasks.map((t) => {
      if (t.id !== event.id) return t;
      switch (event.type) {
        case "progress":
          return { ...t, ...progressFields(t, event, now) };
        case "stateChanged":
          // 离开下载态就把速度清掉，否则"已完成"那一行还挂着一个最后算出来的速度
          return event.state.kind === "downloading"
            ? { ...t, state: event.state }
            : { ...t, state: event.state, speedBps: null, etaText: null };
        case "choicesOffered":
          return { ...t, state: { kind: "awaitingChoice" }, choices: event.kind };
      }
    }),
  };
}

function progressFields(
  t: TaskView,
  event: Extract<EventDto, { type: "progress" }>,
  now: number
): Pick<TaskView, "downloaded" | "total" | "unit" | "speedBps" | "etaText" | "lastTickAt"> {
  const dt = (now - t.lastTickAt) / 1000;
  const dd = event.downloaded - t.downloaded;
  // 分片单位不报速度：那是"片/秒"，混进总速度会得到 "3.0 B/s" 这种假数字。
  // dt 太小（同一批事件）时沿用上一次的值，避免除出天文数字。
  const speedBps =
    t.unit === "bytes" && t.lastTickAt > 0 && dt > 0.2 && dd >= 0 ? dd / dt : t.speedBps;
  const remaining = Math.max(0, event.total - event.downloaded);
  const etaText =
    t.unit === "bytes" && speedBps && speedBps > 0 && remaining > 0
      ? `剩 ${humanizeSeconds(remaining / speedBps)}`
      : null;
  return {
    downloaded: event.downloaded,
    total: event.total,
    unit: event.unit,
    speedBps,
    etaText,
    lastTickAt: now,
  };
}
```

```ts
import { useSyncExternalStore } from "react";
import type { TaskView } from "../lib/types";
import * as ipc from "../lib/ipc";
import { initialState, reduce, type Action, type UiState } from "./reducer";

let state: UiState = initialState;
const listeners = new Set<() => void>();

function emit() {
  for (const l of listeners) l();
}

export const store = {
  subscribe(l: () => void) {
    listeners.add(l);
    return () => listeners.delete(l);
  },
  getSnapshot() {
    return state;
  },
};

export function dispatch(action: Action) {
  const next = reduce(state, action);
  if (next !== state) {
    state = next;
    emit();
    scheduleResyncIfNeeded();
  }
}

let resyncInFlight = false;
function scheduleResyncIfNeeded() {
  if (!state.needsResync || resyncInFlight) return;
  resyncInFlight = true;
  // 不在这里清 needsResync：hydrate 会清。这样连续来几个未知 id 也只拉一次。
  void hydrate().finally(() => {
    resyncInFlight = false;
  });
}

export async function hydrate() {
  const dtos = await ipc.getTasks();
  dispatch({
    kind: "hydrate",
    // 速度/剩余时间是"两次事件之间"的量，全量刷新时无从谈起 —— 一律归零，
    // 否则界面上会挂着上一轮算出来的数字。
    tasks: dtos.map((d) => ({
      ...d,
      choices: null,
      editing: false,
      speedBps: null,
      etaText: null,
      lastTickAt: 0,
    })),
  });
  // 重同步之后，处于"等待选择"却没有候选副本的行，逐个去问 core 要。
  // 这一步就是"丢掉 ChoicesOffered 之后模态框还能弹出来"的唯一保证。
  for (const t of state.tasks) {
    if (t.state.kind === "awaitingChoice" && t.choices === null) {
      const c = await ipc.pendingChoice(t.id);
      if (c) dispatch({ kind: "choices", id: t.id, choices: c });
    }
  }
}

export async function loadSettings() {
  dispatch({ kind: "settings", settings: await ipc.getSettings() });
}

/**
 * 所有命令调用的统一入口。**命令级失败不打断操作**：列一张 toast 就好，
 * 不要把界面卡住或者弹一个必须先关掉的对话框。
 * 用法：`void run(ipc.pause(id))`。
 */
export async function run<T>(p: Promise<T>): Promise<T | undefined> {
  try {
    return await p;
  } catch (e) {
    dispatch({ kind: "pushToast", text: typeof e === "string" ? e : String(e) });
    return undefined;
  }
}

export function dismissToast(index: number) {
  dispatch({ kind: "dismissToast", index });
}

export function useToasts(): string[] {
  return useSyncExternalStore(store.subscribe, store.getSnapshot).toasts;
}

/** 由 <App> 在挂载时调用一次。 */
export async function startBridge() {
  await ipc.onEngineEvent((event) => dispatch({ kind: "event", event }));
  await ipc.onResync((dropped) => dispatch({ kind: "resyncRequested", dropped }));
  await hydrate();
}

export function useTaskList(): TaskView[] {
  return useSyncExternalStore(store.subscribe, store.getSnapshot).tasks;
}

export function useSettings() {
  return useSyncExternalStore(store.subscribe, store.getSnapshot).settings;
}
```

```ts
// 从 egui 版的 format_size / format_speed 移植，行为保持一致：
// 1024 进制、保留一位小数、0 也要显示成 "0 B" 而不是空字符串。

const UNITS = ["B", "KB", "MB", "GB", "TB"];

export function formatSize(bytes: number): string {
  if (bytes <= 0) return "0 B";
  let v = bytes;
  let i = 0;
  while (v >= 1024 && i < UNITS.length - 1) {
    v /= 1024;
    i += 1;
  }
  return i === 0 ? `${Math.round(v)} B` : `${v.toFixed(1)} ${UNITS[i]}`;
}

export function formatSpeed(bps: number): string {
  return `${formatSize(bps)}/s`;
}
```

```ts
export type ThemeMode = "system" | "light" | "dark";

const KEY = "easydownvideo.theme";

export function readThemeMode(): ThemeMode {
  const v = localStorage.getItem(KEY);
  return v === "light" || v === "dark" ? v : "system";
}

export function applyTheme(mode: ThemeMode): void {
  localStorage.setItem(KEY, mode);
  const systemDark = window.matchMedia("(prefers-color-scheme: dark)").matches;
  const dark = mode === "dark" || (mode === "system" && systemDark);
  document.documentElement.dataset.theme = dark ? "dark" : "light";
}

/** 跟随系统时，系统主题变了要跟着变。返回取消订阅函数。 */
export function watchSystemTheme(mode: ThemeMode, onChange: () => void): () => void {
  if (mode !== "system") return () => {};
  const mq = window.matchMedia("(prefers-color-scheme: dark)");
  mq.addEventListener("change", onChange);
  return () => mq.removeEventListener("change", onChange);
}
```

```tsx
import { useTaskList } from "../store/store";
import * as ipc from "../lib/ipc";
import { formatSize } from "../lib/format";

/**
 * "选清晰度"与"选格式"是同一个组件的两种数据。
 *
 * 一个任务处于 awaitingChoice 却**没有候选副本**时（事件被丢掉、或刚重同步过），
 * 这里不发请求也不显示"加载中"就完事 —— store.hydrate() 会去调 pending_choice 补齐。
 * 在补齐之前这一行渲染成"正在获取候选…"，而不是一个没有任何按钮的死界面。
 */
export default function ChoiceDialog() {
  const waiting = useTaskList().filter((t) => t.state.kind === "awaitingChoice");
  if (waiting.length === 0) return null;

  return (
    <>
      {waiting.map((task) => (
        <div
          key={task.id}
          className="fixed inset-0 flex items-center justify-center"
          style={{ background: "rgba(0,0,0,.35)" }}
        >
          <div
            className="w-[460px] max-h-[70vh] overflow-y-auto rounded-lg p-5 shadow-2xl"
            style={{ background: "var(--bg)", border: "1px solid var(--line-strong)" }}
          >
            <h2 className="text-[15px] font-semibold mb-1">选择下载格式</h2>
            <p className="mb-4 truncate" style={{ color: "var(--fg-muted)" }}>
              {task.filename}
            </p>

            {task.choices === null && (
              <p style={{ color: "var(--fg-faint)" }}>正在获取候选…</p>
            )}

            {task.choices?.kind === "hlsVariants" && (
              <div className="grid gap-1.5">
                {task.choices.hlsVariants.map((v, i) => (
                  <button
                    key={v.uri}
                    onClick={() => void ipc.setChoice(task.id, { kind: "variant", index: i })}
                    className="flex justify-between rounded-md px-3 py-2 border text-left"
                    style={{ borderColor: "var(--line-strong)", background: "var(--bg-inset)" }}
                  >
                    <span>
                      {v.resolution ? `${v.resolution[0]}×${v.resolution[1]}` : "未知分辨率"}
                    </span>
                    <span className="tnum" style={{ color: "var(--fg-muted)" }}>
                      {Math.round(v.bandwidth / 1000)} kbps
                    </span>
                  </button>
                ))}
              </div>
            )}

            {task.choices?.kind === "ytdlpFormats" && (
              <div className="grid gap-1.5">
                {task.choices.ytdlpFormats.map((f, i) => (
                  <button
                    key={f.id}
                    onClick={() => void ipc.setChoice(task.id, { kind: "ytdlpFormat", index: i })}
                    className="flex justify-between rounded-md px-3 py-2 border text-left"
                    style={{ borderColor: "var(--line-strong)", background: "var(--bg-inset)" }}
                  >
                    <span>
                      {f.note}（.{f.ext}）
                    </span>
                    <span className="tnum" style={{ color: "var(--fg-muted)" }}>
                      {f.filesize ? formatSize(f.filesize) : "大小未知"}
                    </span>
                  </button>
                ))}
              </div>
            )}

            <div className="flex justify-end mt-4">
              <button onClick={() => void ipc.cancel(task.id)}>取消下载</button>
            </div>
          </div>
        </div>
      ))}
    </>
  );
}
```
