# 视频操作（导航 + 压缩通路）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把「视频操作」从占位页变成可用功能：侧边栏可展开的子菜单、一条完整的本地视频处理通路（选文件 → 调参数 → 排队 → 进度 → 取消 → 产物落盘），本轮只有「压缩」端到端可用。

**Architecture:** 新建独立子系统 `src/core/videoops/`（自己的任务表、队列、并发、事件通道），**不碰下载引擎的任何锁与状态**。事件走自己的 broadcast 通道，`bridge::run` 泛化为通用管道后由 `main.rs` 多 spawn 一次。前端在同一个 store 里加一个 `jobs` 切片。

**Tech Stack:** Rust 2021 / tokio / 内嵌 ffmpeg 9.0.2 / Tauri 2.12.4 / React 19 + TypeScript / vitest / Tailwind 4

**Spec:** `docs/superpowers/specs/2026-10-16-video-ops-design.md`

## Global Constraints

- 语言：界面文案、注释、commit message 全部用中文（仓库既有约定）。
- 界面**不做假按钮**：未实现的操作照实灰显，不做"点了没反应"的控件。
- `core` 是唯一真相源：任务状态活在前端会被窗口重载清掉，一律由 core 持有、前端水合。
- **不新增第三方依赖。** 内嵌 ffmpeg 已经够用（libx264/libx265/svtav1/vpx + videotoolbox）。
- 下载通路的事件枚举（`EngineEvent`）、DTO（`EventDto`）、命令一个字节都不改。
- 产物**绝不覆盖源文件**；失败或取消**绝不留下半截文件**。
- 取消的收尾顺序固定：**先 kill、再等它真的退出、最后才删产物**（顺序反了进程会把半截文件重新写出来）。
- 并发上限写死 1，不做设置项。
- 每次 commit 结尾带 `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

```rust
use std::path::Path;
use std::str::FromStr;

/// 三档质量预设。数值取自 spec 第 6.1 节。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum CompressPreset {
    Small,
    Balanced,
    High,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Encoder {
    /// **= Software。** 见 `encoder_name` 的说明。
    Auto,
    Hardware,
    Software,
}

impl FromStr for CompressPreset {
    type Err = anyhow::Error;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s {
            "small" => Ok(Self::Small),
            "balanced" => Ok(Self::Balanced),
            "high" => Ok(Self::High),
            other => Err(anyhow::anyhow!("未知的压缩档位: {other}")),
        }
    }
}

impl FromStr for Encoder {
    type Err = anyhow::Error;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s {
            "auto" => Ok(Self::Auto),
            "hardware" => Ok(Self::Hardware),
            "software" => Ok(Self::Software),
            other => Err(anyhow::anyhow!("未知的编码器: {other}")),
        }
    }
}

/// `(crf, qv, audio_kbps)`。
///
/// **两套质量刻度方向相反**：CRF 越小越清晰，`-q:v` 越大越清晰。写反了不会报错，
/// 只会让"小体积"档产出比"高画质"还大的文件。
pub fn preset_defaults(preset: CompressPreset) -> (u8, u8, u32) {
    match preset {
        CompressPreset::Small => (28, 50, 96),
        CompressPreset::Balanced => (24, 65, 128),
        CompressPreset::High => (20, 80, 192),
    }
}

#[derive(Clone, Debug, PartialEq, Eq)]
pub struct CompressParams {
    pub preset: CompressPreset,
    pub encoder: Encoder,
    /// `None` = 保持原样。给了值表示"最长边不超过它"。
    pub max_height: Option<u32>,
    /// `None` = 用预设自带的值。
    pub crf: Option<u8>,
    pub qv: Option<u8>,
    pub audio_kbps: Option<u32>,
}

/// 「自动」落到软件 x264：体积画质比最好且可预测。
/// 默认走硬件等于默认降质 —— 硬件是给"要快"的人显式开的选项。
fn resolved_encoder(e: Encoder) -> Encoder {
    match e {
        Encoder::Auto => Encoder::Software,
        other => other,
    }
}

/// 拼出完整的 ffmpeg 参数（不含可执行文件本身）。
///
/// **产物一律先写 `<output>.part`。** 直接写目标名的话，中途被杀会留下一个半截文件，
/// 而"文件存在"在很多地方就等于"已完成"。成功后由调用方 rename —— 同一文件系统内
/// 原子，所以"改过名"等价于"完整"。
pub fn compress_args(input: &Path, output: &Path, p: &CompressParams) -> Vec<String> {
    let (crf_default, qv_default, kbps_default) = preset_defaults(p.preset);
    let encoder = resolved_encoder(p.encoder);

    let mut a: Vec<String> = vec![
        "-nostdin".into(), // 不阻断的话 ffmpeg 会去读 stdin，可能一直等在那里
        "-hide_banner".into(),
        "-nostats".into(),   // 正常的进度噪声不要混进 stderr，那里只留错误
        "-progress".into(),
        "pipe:1".into(),
        "-y".into(),
        "-i".into(),
        input.to_string_lossy().into_owned(),
    ];

    // 质量旋钮必须**分成两条路径**，不能"换个编码器、质量参数照旧"：
    // VideoToolbox 对 -crf 是静默忽略的（实测 crf 18 与 crf 40 逐字节相同）。
    match encoder {
        Encoder::Hardware => {
            a.push("-c:v".into());
            a.push("h264_videotoolbox".into());
            a.push("-q:v".into());
            a.push(p.qv.unwrap_or(qv_default).to_string());
        }
        _ => {
            a.push("-c:v".into());
            a.push("libx264".into());
            a.push("-preset".into());
            a.push("veryfast".into());
            a.push("-crf".into());
            a.push(p.crf.unwrap_or(crf_default).to_string());
        }
    }

    // -2 让宽度按比例算出并取偶数。写成固定宽度会拉伸画面；
    // 写成奇数宽度则某些编码器直接拒绝。
    if let Some(h) = p.max_height {
        a.push("-vf".into());
        a.push(format!("scale=-2:{h}"));
    }

    a.push("-c:a".into());
    a.push("aac".into());
    a.push("-b:a".into());
    a.push(format!("{}k", p.audio_kbps.unwrap_or(kbps_default)));

    // 最后一个是输出路径（先写临时名）
    a.push(format!("{}.part", output.to_string_lossy()));
    a
}
```

- [ ] **Step 5: 校准 VideoToolbox 的三个 `-q:v` 值**

spec 第 6.1 节的 50/65/80 是按两组实测点内插的**起点值**，必须核准。判据有两条，
第二条才是真正会伤到用户的：

1. **同档 VT 与 x264 的体积比落在 0.8–1.5**（不是 2.0 —— 见下面的实测）。
2. **任意一档的产物都不得大于源文件。** 用户点的是"压缩"，拿到一个更大的文件就是白干。

> 首次执行的结果：50/65/80 经实测是**错的** —— 比值 1.56/1.70/1.96，而高画质一档产出
> 9015621 字节，**比源文件 6104040 还大 48%**。判据 1 在 2.0 下会放过它，判据 2 不会。
> 扫描后定为 **38 / 52 / 60**，实测比值 1.05 / 1.04 / 0.99，三档均小于源文件。
> 硬件编码器在同等感知质量下本来就比 x264 占地方，所以同档 `q:v` 必须显著低于
> "按刻度均匀内插"的结果。

```rust
use std::path::Path;

/// 从 `ffmpeg -i <file>` 的 stderr 里抠出时长（秒）。
///
/// **为什么要写这个**：内嵌的只有 ffmpeg，没有 ffprobe（`vendor/ffmpeg/` 下就一个二进制）。
/// 不带输出文件时 ffmpeg 会以非零码退出，那是正常的 —— 我们要的就是它打在 stderr 上的信息。
///
/// 拿不到时返回 `None` 而不是 0：调用方据此把进度退化成不确定态。
/// 返回 0 会让进度条要么永远停在 0%、要么在除法里炸掉。
pub fn parse_duration(stderr: &str) -> Option<f64> {
    let line = stderr
        .lines()
        .find(|l| l.contains("Duration:"))?
        .trim();
    let rest = line.split("Duration:").nth(1)?.trim();
    let stamp = rest.split(',').next()?.trim();
    // 格式固定是 HH:MM:SS.ss，`N/A` 会在这里被拆成 1 段而落空
    let parts: Vec<&str> = stamp.split(':').collect();
    if parts.len() != 3 {
        return None;
    }
    let h: f64 = parts[0].trim().parse().ok()?;
    let m: f64 = parts[1].trim().parse().ok()?;
    let s: f64 = parts[2].trim().parse().ok()?;
    Some(h * 3600.0 + m * 60.0 + s)
}

/// 真去跑一次 `ffmpeg -i`。失败、超时、解析不出来都是 `None` —— 这个函数不产生错误，
/// 因为"拿不到时长"不该阻断任务。
pub async fn media_duration(ffmpeg: &Path, input: &Path) -> Option<f64> {
    // 不带输出文件：ffmpeg 打印完流信息就以非零码退出，这正是我们要的
    let out = tokio::process::Command::new(ffmpeg)
        .arg("-hide_banner")
        .arg("-i")
        .arg(input)
        .output()
        .await
        .ok()?;
    parse_duration(&String::from_utf8_lossy(&out.stderr))
}
```

```rust
use std::path::Path;
use std::process::Stdio;
use std::sync::Arc;

use anyhow::{anyhow, Context};
use tokio::io::{AsyncBufReadExt, BufReader};
use tokio_util::sync::CancellationToken;

#[derive(Debug, PartialEq, Eq)]
pub enum JobOutcome {
    Done,
    /// token 被取消。子进程已被杀掉并收尸，半截产物已删除。
    Interrupted,
}

/// 解析 `-progress pipe:1` 的一行，换算成 0.0–1.0。
///
/// **`out_time_ms` 也是微秒。** ffmpeg 这个字段名是错的：它和 `out_time_us` 一样
/// 输出微秒（实测 5 秒的片子两者都是 4933333）。照字面当毫秒用，进度会永远停在
/// 0.5%，而且看起来像卡死而不像报错。
///
/// 不相关的行（`frame=`、`progress=continue` …）与解析不出来的值一律 `None`。
pub fn parse_progress_fraction(line: &str, duration_secs: f64) -> Option<f64> {
    if duration_secs <= 0.0 {
        // 没有分母就不编一个分数出来 —— 调用方据此显示不确定态
        return None;
    }
    let raw = line
        .strip_prefix("out_time_us=")
        .or_else(|| line.strip_prefix("out_time_ms="))?;
    let micros: f64 = raw.trim().parse().ok()?;
    let frac = micros / (duration_secs * 1_000_000.0);
    Some(frac.clamp(0.0, 1.0))
}

/// 跑一次 ffmpeg，全程可被 `cancel` 打断。
///
/// 收尾顺序**固定**：先 kill、再等它真的退出、最后才删产物。顺序反了的话，
/// kill 只是发信号，进程可能还有一次写在做 —— 不等它就删，它随后会把半截文件
/// 重新写出来，用户会在目录里看到一个打不开的 mp4。
///
/// `part_path` 由本函数负责清理（失败或取消时）；成功时的 rename 由调用方做。
pub async fn run_job(
    ffmpeg: &Path,
    args: &[String],
    part_path: &Path,
    duration_secs: Option<f64>,
    on_progress: Arc<dyn Fn(f64) + Send + Sync>,
    cancel: &CancellationToken,
) -> anyhow::Result<JobOutcome> {
    let mut cmd = tokio::process::Command::new(ffmpeg);
    cmd.args(args);
    cmd.stdout(Stdio::piped()).stderr(Stdio::piped());
    // 兜底：future 因为别的原因被 drop（例如整个 runtime 收尾）时，Child 一并 drop，
    // 进程同样会被收掉。与 build_remux 同样的理由。
    cmd.kill_on_drop(true);
    let mut child = cmd.spawn().context("spawn ffmpeg")?;

    // stdout 是进度（`-progress pipe:1`），stderr 是错误。两条管道都必须有人抽干 ——
    // 没人读的话 ffmpeg 写满 64KB 管道缓冲就会卡在 write 上永不退出。
    let stdout = child.stdout.take();
    let progress_task = tokio::spawn(async move {
        let Some(out) = stdout else { return };
        let mut lines = BufReader::new(out).lines();
        while let Ok(Some(line)) = lines.next_line().await {
            if let Some(frac) = parse_progress_fraction(&line, duration_secs.unwrap_or(0.0)) {
                on_progress(frac);
            }
        }
    });
    let mut err_pipe = child.stderr.take();
    let err_task = tokio::spawn(async move {
        let mut buf = Vec::new();
        if let Some(e) = err_pipe.as_mut() {
            use tokio::io::AsyncReadExt;
            let _ = e.read_to_end(&mut buf).await;
        }
        buf
    });

    // `-progress` 在正常结束时也会写出 `progress=end`，所以成功时也补一次 100%
    tokio::select! {
        status = child.wait() => {
            let status = status.context("wait ffmpeg")?;
            let _ = progress_task.await; // 进程已退出，stdout 会 EOF，读循环自然收尾
            let stderr = err_task.await.unwrap_or_default();
            if !status.success() {
                std::fs::remove_file(part_path).ok();
                return Err(anyhow!("ffmpeg 失败: {}", summarize_stderr(&stderr)));
            }
            Ok(JobOutcome::Done)
        }
        _ = cancel.cancelled() => {
            let _ = child.start_kill();
            let _ = child.wait().await;
            let _ = progress_task.await;
            let _ = err_task.await;
            std::fs::remove_file(part_path).ok();
            Ok(JobOutcome::Interrupted)
        }
    }
}

/// 错误摘要：取最后 20 行、且总长不超过 2 KB。
///
/// ffmpeg 的错误总在尾部，而它跑一个长任务能吐出几千行 —— 全量塞进界面没有意义。
pub fn summarize_stderr(bytes: &[u8]) -> String {
    let text = String::from_utf8_lossy(bytes);
    let lines: Vec<&str> = text.lines().filter(|l| !l.trim().is_empty()).collect();
    let tail = if lines.len() > 20 { &lines[lines.len() - 20..] } else { &lines[..] };
    let mut joined = tail.join("\n");
    while joined.len() > 2048 {
        // 从头丢，保住尾部（错误在那头）
        match joined.find('\n') {
            Some(i) => joined = joined[i + 1..].to_string(),
            None => break,
        }
    }
    joined
}
```

```rust
/// 收敛：一直收事件直到任务到终态或超时。事件是唯一的观察窗口，
/// 所以测试必须像前端那样订阅它，而不是轮询内部状态。
async fn wait_terminal(
    rx: &mut broadcast::Receiver<VideoOpEvent>,
    id: u64,
    secs: u64,
) -> JobState {
    let deadline = tokio::time::Instant::now() + std::time::Duration::from_secs(secs);
    loop {
        let left = deadline.saturating_duration_since(tokio::time::Instant::now());
        match tokio::time::timeout(left, rx.recv()).await {
            Ok(Ok(VideoOpEvent::StateChanged { id: i, state })) if i == id => {
                if matches!(state, JobState::Done | JobState::Failed(_) | JobState::Canceled) {
                    return state;
                }
            }
            Ok(Ok(_)) => {}
            _ => panic!("等终态超时"),
        }
    }
}

/// 取消一个**排队中**（还没轮到）的任务：必须立刻停在 Canceled，且不能自己复活。
#[tokio::test(flavor = "multi_thread", worker_threads = 2)]
async fn cancelling_a_queued_job_stays_cancelled() {
    let dir = tempfile::tempdir().unwrap();
    let ffmpeg = ensure_ffmpeg(dir.path()).unwrap();
    let src = dir.path().join("src.mp4");
    // 20 秒 1080p60，慢到足够把第二个任务堵在队列里
    make_src(&ffmpeg, &src, 20).await;
    let src2 = dir.path().join("src2.mp4");
    std::fs::copy(&src, &src2).unwrap();

    let rt = tokio::runtime::Handle::current();
    let ops = VideoOps::new(rt, dir.path().to_path_buf());
    let mut rx = ops.events();

    let first = ops.add_compress_job(src, dir.path().to_path_buf(), params()).await.unwrap();
    let second = ops.add_compress_job(src2, dir.path().to_path_buf(), params()).await.unwrap();
    // 并发上限是 1，第二个必然还在排队
    tokio::time::sleep(std::time::Duration::from_millis(300)).await;
    assert_eq!(
        ops.list_jobs().iter().find(|j| j.id == second).unwrap().state,
        JobState::Queued
    );

    ops.cancel(second);
    assert_eq!(wait_terminal(&mut rx, second, 10).await, JobState::Canceled);
    // 取消之后不该再出现这个 id 的任何 StateChanged 把它复活
    tokio::time::sleep(std::time::Duration::from_millis(300)).await;
    assert_eq!(
        ops.list_jobs().iter().find(|j| j.id == second).unwrap().state,
        JobState::Canceled,
        "被取消的排队任务不得复活"
    );
    ops.cancel(first);
}
```

```rust
pub mod ffmpeg_job;
pub mod media_info;
pub mod presets;

use std::collections::{HashMap, VecDeque};
use std::path::PathBuf;
use std::sync::atomic::{AtomicU64, Ordering};
use std::sync::{Arc, Mutex};

use tokio::runtime::Handle;
use tokio::sync::broadcast;
use tokio_util::sync::CancellationToken;

use crate::core::ffmpeg::ensure_ffmpeg;
use crate::core::direct::unique_path_avoiding;
use ffmpeg_job::{run_job, JobOutcome};
use presets::{compress_args, CompressParams};

pub type JobId = u64;

#[derive(Clone, Debug, PartialEq, Eq)]
pub enum JobState {
    Queued,
    Running,
    Done,
    Failed(String),
    Canceled,
}

#[derive(Clone, Debug, PartialEq)]
pub struct JobSnapshot {
    pub id: JobId,
    pub label: String,
    pub input: PathBuf,
    pub output: PathBuf,
    pub state: JobState,
    pub progress: Option<f64>,
}

#[derive(Clone, Debug)]
pub enum VideoOpEvent {
    Added { id: JobId },
    StateChanged { id: JobId, state: JobState },
    Progress { id: JobId, fraction: f64 },
    Removed { id: JobId },
}

fn is_terminal(s: &JobState) -> bool {
    matches!(s, JobState::Done | JobState::Failed(_) | JobState::Canceled)
}

struct JobEntry {
    label: String,
    input: PathBuf,
    output: PathBuf,
    /// 实际要写的临时名（`<output>.part`）与产物最终路径并存，取消时删的是它
    args: Vec<String>,
    state: JobState,
    progress: Option<f64>,
    cancel: CancellationToken,
}

struct Inner {
    rt: Handle,
    data_dir: PathBuf,
    ffmpeg: Mutex<Option<PathBuf>>,
    jobs: Mutex<HashMap<JobId, JobEntry>>,
    queue: Mutex<VecDeque<JobId>>,
    tx: broadcast::Sender<VideoOpEvent>,
    next_id: AtomicU64,
}

#[derive(Clone)]
pub struct VideoOps {
    inner: Arc<Inner>,
}

/// 并发上限**写死 1**：转码吃满 CPU，与下载抢资源只会让两边都变慢。
/// 要放开时再加设置项，现在加就是一个没人调过的旋钮。
const MAX_ACTIVE_JOBS: usize = 1;

impl VideoOps {
    pub fn new(rt: Handle, data_dir: PathBuf) -> Self {
        let (tx, _) = broadcast::channel(256);
        Self {
            inner: Arc::new(Inner {
                rt,
                data_dir,
                ffmpeg: Mutex::new(None),
                jobs: Mutex::new(HashMap::new()),
                queue: Mutex::new(VecDeque::new()),
                tx,
                next_id: AtomicU64::new(1),
            }),
        }
    }

    pub fn events(&self) -> broadcast::Receiver<VideoOpEvent> {
        self.inner.tx.subscribe()
    }

    /// 解出内嵌 ffmpeg（已有的 `ensure_ffmpeg` 会校验哈希、复用已解出的那份）。
    fn ffmpeg(&self) -> anyhow::Result<PathBuf> {
        if let Some(p) = self.inner.ffmpeg.lock().unwrap().as_ref() {
            return Ok(p.clone());
        }
        let p = ensure_ffmpeg(&self.inner.data_dir)?;
        *self.inner.ffmpeg.lock().unwrap() = Some(p.clone());
        Ok(p)
    }

    pub fn list_jobs(&self) -> Vec<JobSnapshot> {
        let jobs = self.inner.jobs.lock().unwrap();
        let mut out: Vec<JobSnapshot> = jobs
            .iter()
            .map(|(id, j)| JobSnapshot {
                id: *id,
                label: j.label.clone(),
                input: j.input.clone(),
                output: j.output.clone(),
                state: j.state.clone(),
                progress: j.progress,
            })
            .collect();
        out.sort_by_key(|s| s.id);
        out
    }

    /// 入队一次压缩。**校验一律在这里做完**：输入不存在、输出目录不可写、文件里没有
    /// 视频流，都在入队那一刻就报错，不要排进队列跑一半才失败 —— 那时用户已经等了半天。
    ///
    /// 是 async 只因为"有没有视频流"要跑一次 `ffmpeg -i`。这条校验不能省：
    /// 纯音频输入**不会**让 ffmpeg 报错，它会老老实实编出一个只有音轨的 mp4 并退出 0，
    /// 用户点的是"压缩视频"却拿到一个没有画面的文件 —— 那种"看起来成功了"的结果
    /// 比直接报错坏得多。
    pub async fn add_compress_job(
        &self,
        input: PathBuf,
        output_dir: PathBuf,
        params: CompressParams,
    ) -> anyhow::Result<JobId> {
        if !input.is_file() {
            anyhow::bail!("找不到输入文件：{}", input.display());
        }
        let ffmpeg = self.ffmpeg()?;
        let media = media_info::inspect(&ffmpeg, &input).await?;
        if !media.has_video {
            anyhow::bail!(
                "这个文件里读不到视频流（可能是纯音频，或者文件已损坏）：{}",
                input.display()
            );
        }
        if !output_dir.is_dir() {
            anyhow::bail!("输出目录不存在：{}", output_dir.display());
        }
        // 真写一个探针文件，而不是查权限位 —— 权限位在 ACL、只读卷、网络盘上都不作数
        let probe = output_dir.join(".easydownvideo-write-probe");
        std::fs::write(&probe, b"")
            .map_err(|e| anyhow::anyhow!("输出目录不可写（{}）：{e}", output_dir.display()))?;
        std::fs::remove_file(&probe).ok();

        let stem = input
            .file_stem()
            .and_then(|s| s.to_str())
            .unwrap_or("video")
            .to_string();
        // 重名让路成 " (1)"、" (2)" —— 与下载那边的约定一致（同一个 helper）。
        // **绝不覆盖源文件**：源文件若正好叫 `<stem>-压缩.mp4`，这里会自动让到下一个名字。
        let output = unique_path_avoiding(&output_dir, &format!("{stem}-压缩.mp4"), |_| false);
        let args = compress_args(&input, &output, &params);

        let id = self.inner.next_id.fetch_add(1, Ordering::SeqCst);
        let label = format!("压缩 · {}", preset_label(params.preset));
        self.inner.jobs.lock().unwrap().insert(
            id,
            JobEntry {
                label,
                input,
                output,
                args,
                state: JobState::Queued,
                progress: None,
                cancel: CancellationToken::new(),
            },
        );
        self.inner.queue.lock().unwrap().push_back(id);
        let _ = self.inner.tx.send(VideoOpEvent::Added { id });
        self.pump();
        Ok(id)
    }

    pub fn cancel(&self, id: JobId) {
        let (should_kill, token) = {
            let mut jobs = self.inner.jobs.lock().unwrap();
            let Some(j) = jobs.get_mut(&id) else { return };
            if is_terminal(&j.state) {
                return;
            }
            let was_queued = j.state == JobState::Queued;
            // 排队中的任务没有 worker 会来收尾，所以状态要在这里直接落定；
            // 运行中的交给 worker（它会把状态推到 Canceled 并清掉半截产物）。
            if was_queued {
                j.state = JobState::Canceled;
            }
            (true, j.cancel.clone())
        };
        if should_kill {
            token.cancel();
        }
        // 取消的是排队中的任务时，worker 不会再来发事件，这里补一条
        let state = self.inner.jobs.lock().unwrap().get(&id).map(|j| j.state.clone());
        if let Some(s) = state {
            let _ = self.inner.tx.send(VideoOpEvent::StateChanged { id, state: s });
        }
        self.pump(); // 空出一个槽，后面排队的可以动了
    }

    /// 只对终态任务生效。返回 `false` 表示拒绝（还在跑，或本来就不在列表里）。
    pub fn remove(&self, id: JobId) -> bool {
        let removed = {
            let mut jobs = self.inner.jobs.lock().unwrap();
            match jobs.get(&id) {
                Some(j) if is_terminal(&j.state) => {
                    jobs.remove(&id);
                    true
                }
                _ => false,
            }
        };
        if removed {
            let _ = self.inner.tx.send(VideoOpEvent::Removed { id });
            self.pump();
        }
        removed
    }

    /// 启动队列里下一个能跑的。与下载引擎同构：**"读活跃数 → 判上限 → 置状态"
    /// 必须在同一个锁里**，拆开的话两个线程会同时读到"还有空位"并各自启动一个，超出上限。
    fn pump(&self) {
        loop {
            let started = {
                let mut jobs = self.inner.jobs.lock().unwrap();
                let active = jobs.values().filter(|j| j.state == JobState::Running).count();
                if active >= MAX_ACTIVE_JOBS {
                    return;
                }
                let Some(id) = self.inner.queue.lock().unwrap().pop_front() else {
                    return;
                };
                match jobs.get_mut(&id) {
                    // 只有仍处于 Queued 才启动：排队期间被取消的任务 id 还在队列里，
                    // 没有这道闸 pump 会把它拉起来 —— 用户明明点了取消，它却自己复活。
                    Some(j) if j.state == JobState::Queued => {
                        j.state = JobState::Running;
                        j.cancel = CancellationToken::new();
                        Some((
                            j.args.clone(),
                            j.output.clone(),
                            j.cancel.clone(),
                        ))
                    }
                    _ => None,
                }
            };
            let Some((args, output, cancel)) = started else { continue };

            let _ = self.inner.tx.send(VideoOpEvent::StateChanged {
                id,
                state: JobState::Running,
            });

            let engine = self.clone();
            let tx = self.inner.tx.clone();
            self.inner.rt.spawn(async move {
                let Some(input) = engine.job_input(id) else {
                    return; // 起 worker 之前就被移除了，没有收尾可言
                };
                let outcome = async {
                    let ffmpeg = engine.ffmpeg()?;
                    // 时长只为进度条服务，拿不到就退化成不确定态，绝不阻断任务。
                    let duration = media_info::inspect(&ffmpeg, &input).await.ok().and_then(|m| m.duration_secs);
                    let tx_progress = tx.clone();
                    // 进度要**同时**落进内存状态与发事件：只发事件的话，重同步之后
                    // 列表里读到的进度会退回上一次事件的值（水合读的是 JobEntry）。
                    let engine_progress = engine.clone();
                    let on_progress: Arc<dyn Fn(f64) + Send + Sync> = Arc::new(move |f| {
                        engine_progress.note_progress(id, f);
                        let _ = tx_progress.send(VideoOpEvent::Progress { id, fraction: f });
                    });
                    run_job(&ffmpeg, &args, &output, duration, on_progress, &cancel).await
                }
                .await;

                match outcome {
                    // rename 由 run_job 自己做完 —— 它返回 Done 就意味着产物已在 output 上就位。
                    Ok(JobOutcome::Done) => engine.finish(id, JobState::Done),
                    Ok(JobOutcome::Interrupted) => engine.finish(id, JobState::Canceled),
                    Err(e) => engine.finish(id, JobState::Failed(format!("{e:#}"))),
                }
                engine.pump(); // 空出一个槽
            });
        }
    }

    fn job_input(&self, id: JobId) -> Option<PathBuf> {
        self.inner.jobs.lock().unwrap().get(&id).map(|j| j.input.clone())
    }

    /// 进度落进内存状态。列表水合时读的就是它。
    fn note_progress(&self, id: JobId, fraction: f64) {
        if let Some(j) = self.inner.jobs.lock().unwrap().get_mut(&id) {
            j.progress = Some(fraction);
        }
    }

    /// 落终态并发事件。**状态以这里为唯一出口** —— 所有分支都走它，
    /// 保证界面看到的终态与内部状态永远一致。
    fn finish(&self, id: JobId, state: JobState) {
        let changed = {
            let mut jobs = self.inner.jobs.lock().unwrap();
            match jobs.get_mut(&id) {
                Some(j) => {
                    // 运行中被取消的任务会走到这里（worker 看到 Interrupted），
                    // 但用户已经点过取消了 —— 以用户的取消为准，不覆盖成别的。
                    if j.state == JobState::Canceled {
                        false
                    } else {
                        j.state = state.clone();
                        if state == JobState::Done {
                            j.progress = Some(1.0);
                        }
                        true
                    }
                }
                None => false,
            }
        };
        if changed {
            let _ = self.inner.tx.send(VideoOpEvent::StateChanged { id, state });
        }
    }
}

        presets::CompressPreset::Balanced => "均衡",
        presets::CompressPreset::High => "高画质",
    }
```

```rust
/// 一条通道的转发循环。
///
/// **泛化而不是复制**：`Lagged → 排空残余 → 发 resync` 那套推理（连同它防的那个
/// "旧事件晚于全量快照落地、把正确状态盖回去"的缺陷）是整个桥存在的理由，
/// 复制第二份就等于给了它一处将来只改一边的机会。两条通道各调一次本函数即可。
pub async fn run<S, E>(
    sink: Arc<S>,
    mut rx: broadcast::Receiver<E>,
    to_json: fn(E) -> serde_json::Value,
    event_name: &'static str,
) where
    S: EventSink,
    E: Clone + Send + 'static,
{
    loop {
        match rx.recv().await {
            Ok(ev) => sink.emit(event_name, to_json(ev)),
            Err(broadcast::error::RecvError::Lagged(n)) => {
                let suppressed = drain_stale(&mut rx);
                sink.emit(RESYNC, serde_json::json!({ "dropped": n + suppressed }));
            }
            Err(broadcast::error::RecvError::Closed) => break,
        }
    }
}
```

```ts
    case "hydrateJobs": {
      // 整体替换，不做合并：core 是唯一真相源。
      // 进度也在里面 —— 重同步之后速度/分数这类"两次事件之间的量"由 core 报来，
      // 视频任务的进度本来就是全局量，不需要像下载那边那样归零。
      return { ...state, jobs: action.jobs, needsResync: false };
    }
    case "videoEvent": {
      const { event } = action;
      if (event.type === "added") {
        // 事件里只有 id，没有可显示的内容。不在这里编一行出来 —— 编出来的一行
        // 在随后的 hydrate 里还要被替换掉，等于凭空多一个中间态。
        return { ...state, needsResync: true };
      }
      if (event.type === "removed") {
        const exists = state.jobs.some((j) => j.id === event.id);
        if (!exists) return { ...state, needsResync: true };
        return { ...state, jobs: state.jobs.filter((j) => j.id !== event.id), needsResync: false };
      }
      const known = state.jobs.some((j) => j.id === event.id);
      if (!known) {
        // 与下载事件同义：可能事件先于水合到达，记一笔去拉全量。
        return { ...state, needsResync: true };
      }
      const jobs = state.jobs.map((j): JobView => {
        if (j.id !== event.id) return j;
        if (event.type === "progress") return { ...j, progress: event.fraction };
        return { ...j, state: event.state };
      });
      return { ...state, jobs, needsResync: false };
    }
```

```ts
import type { JobStateDto } from "./types";

export function jobStateLabel(state: JobStateDto): string {
  switch (state.kind) {
    case "queued": return "排队中";
    case "running": return "处理中";
    case "done": return "已完成";
    case "canceled": return "已取消";
    // 失败原因直接带出来：这是用户唯一能看到的线索，藏进折叠区等于没有
    case "failed": return `失败：${state.message}`;
  }
}

/** `null` = 时长未知。界面显示不确定态的进度条，**绝不编一个 0%** —— 那看着像卡死。 */
export function jobPct(progress: number | null): number | null {
  if (progress === null) return null;
  return Math.round(Math.min(1, Math.max(0, progress)) * 100);
}
```

```tsx
import { useEffect, useState } from "react";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import * as ipc from "../lib/ipc";
import { run, useSettings } from "../store/store";
import { formatSize } from "../lib/format";
import JobList from "../components/JobList";
import type { VideoOp } from "../lib/videoOps";
import { opLabel } from "../lib/videoOps";

const PRESETS = [
  { value: "small", label: "小体积" },
  { value: "balanced", label: "均衡" },
  { value: "high", label: "高画质" },
] as const;

const ENCODERS = [
  { value: "auto", label: "自动" },
  { value: "hardware", label: "硬件加速" },
  { value: "software", label: "软件" },
] as const;

const HEIGHTS = [
  { value: 0, label: "保持原样" },
  { value: 1080, label: "1080p" },
  { value: 720, label: "720p" },
] as const;

/** 与 core 的 preset_defaults 一一对应。**只用于"切档位时把高级项重置成该档的值"**,
 *  真正生效的数值始终来自 core —— 界面不参与计算质量参数。 */
const PRESET_CRF: Record<string, number> = { small: 28, balanced: 24, high: 20 };
const PRESET_QV: Record<string, number> = { small: 50, balanced: 65, high: 80 };

export default function VideoOpPage({ op }: { op: VideoOp }) {
  const settings = useSettings();
  const [input, setInput] = useState<string | null>(null);
  const [info, setInfo] = useState<{ durationSecs: number | null; sizeBytes: number } | null>(null);
  const [preset, setPreset] = useState<string>("balanced");
  const [encoder, setEncoder] = useState<string>("auto");
  const [maxHeight, setMaxHeight] = useState<number>(0);
  const [showAdvanced, setShowAdvanced] = useState(false);
  const [crf, setCrf] = useState(PRESET_CRF.balanced);
  const [qv, setQv] = useState(PRESET_QV.balanced);
  const [outputDir, setOutputDir] = useState<string | null>(null);
  const [busy, setBusy] = useState(false);

  // 输出目录默认跟随设置里的下载目录,但允许这一页临时改（不落盘、不污染设置）。
  useEffect(() => {
    if (settings && outputDir === null) setOutputDir(settings.downloadDir);
  }, [settings, outputDir]);

  async function pick() {
    const p = await run(ipc.pickVideoFile());
    if (!p) return;
    setInput(p);
    setInfo(null);
    const i = await run(ipc.probeVideo(p));
    if (i) setInfo(i);
  }

  function choosePreset(v: string) {
    setPreset(v);
    // 切档位就把高级项重置成该档的值 —— 否则用户改了 CRF 再换档位,
    // 会得到一个"均衡档 + 小体积的 CRF"的四不像,而界面上看不出这件事。
    setCrf(PRESET_CRF[v]);
    setQv(PRESET_QV[v]);
  }

  async function start() {
    if (!input || !outputDir || busy) return;
    setBusy(true);
    try {
      const id = await run(
        ipc.addCompressJob({
          input, outputDir, preset, encoder,
          maxHeight: maxHeight === 0 ? null : maxHeight,
          crf: showAdvanced ? crf : null,
          qv: showAdvanced ? qv : null,
          audioKbps: null,
        })
      );
      // 入队成功才清空选择:失败时把文件留在框里,用户要重试的就是它
      if (id !== undefined) {
        setInput(null);
        setInfo(null);
      }
    } finally {
      setBusy(false);
    }
  }

  if (op !== "compress") {
    // 路由理论上只把 compress 送进来(Task 8 的 ready 闸),但类型上 VideoOp 是五个的联合。
    // 不假装能用 —— 照实说。
    return (
      <div className="h-full flex items-center justify-center" style={{ color: "var(--fg-muted)" }}>
        {opLabel(op)}还没做
      </div>
    );
  }

  const durationText =
    info?.durationSecs != null
      ? new Date(info.durationSecs * 1000).toISOString().substring(14, 19)
      : "时长未知";

  return (
    <>
      <div className="flex items-center gap-2 py-4">
        <Input readOnly value={input ?? ""} placeholder="选一个视频文件…" />
        <Button onClick={() => void pick()}>选择文件</Button>
      </div>

      {info && (
        <p className="text-[12px] mb-4" style={{ color: "var(--fg-muted)" }}>
          源文件 {formatSize(info.sizeBytes)} · {durationText}
        </p>
      )}

      <label className="block mb-5">
        <span style={{ color: "var(--fg-muted)" }}>质量</span>
        <div className="flex gap-1 mt-1.5">
          {PRESETS.map((p) => (
            <button
              key={p.value}
              onClick={() => choosePreset(p.value)}
              className="h-8 px-3 rounded-md text-[13px] border transition-colors"
              style={{
                borderColor: "var(--line-strong)",
                background: preset === p.value ? "var(--nav-sel)" : "transparent",
                color: "var(--fg)",
                fontWeight: preset === p.value ? 500 : 400,
              }}
            >
              {p.label}
            </button>
          ))}
        </div>
      </label>

      <label className="block mb-5">
        <span style={{ color: "var(--fg-muted)" }}>保存到</span>
        <Input
          className="mt-1.5"
          value={outputDir ?? ""}
          onChange={(e) => setOutputDir(e.target.value)}
        />
        <span className="text-[12px]" style={{ color: "var(--fg-faint)" }}>
          只影响这次操作，不改设置里的下载目录。
        </span>
      </label>

      <button
        className="flex items-center gap-1 text-[13px] mb-3"
        onClick={() => setShowAdvanced((v) => !v)}
        aria-expanded={showAdvanced}
      >
        {showAdvanced ? "▾" : "▸"} 高级
      </button>

      {showAdvanced && (
        <div className="mb-5 pl-3 border-l" style={{ borderColor: "var(--line)" }}>
          <label className="block mb-4">
            <span style={{ color: "var(--fg-muted)" }}>编码器</span>
            <select
              className="w-48 mt-1.5 h-8 rounded-lg border px-2 text-[13px] bg-[var(--bg-inset)] border-[var(--line-strong)] text-[var(--fg)]"
              value={encoder}
              onChange={(e) => setEncoder(e.target.value)}
            >
              {ENCODERS.map((x) => (
                <option key={x.value} value={x.value}>{x.label}</option>
              ))}
            </select>
            <span className="block text-[12px]" style={{ color: "var(--fg-faint)" }}>
              「自动」用软件编码：体积画质比最好。硬件更快，但同样档位体积更大。
            </span>
          </label>

          <label className="block mb-4">
            <span style={{ color: "var(--fg-muted)" }}>分辨率</span>
            <select
              className="w-48 mt-1.5 h-8 rounded-lg border px-2 text-[13px] bg-[var(--bg-inset)] border-[var(--line-strong)] text-[var(--fg)]"
              value={maxHeight}
              onChange={(e) => setMaxHeight(Number(e.target.value))}
            >
              {HEIGHTS.map((x) => (
                <option key={x.value} value={x.value}>{x.label}</option>
              ))}
            </select>
          </label>

          {/* 质量微调只在软件编码下出现：硬件根本不看 CRF,显示出来就是误导。
              两种刻度的方向相反,所以标签必须写清哪头是"更小体积"。 */}
          {encoder !== "hardware" ? (
            <label className="block">
              <span style={{ color: "var(--fg-muted)" }}>画质（数值越小体积越小）</span>
              <Input
                type="number" className="w-24 mt-1.5" value={crf}
                onChange={(e) => setCrf(Number(e.target.value))}

          ) : (
            <label className="block">
              <span style={{ color: "var(--fg-muted)" }}>画质（数值越大体积越大）</span>

                type="number" className="w-24 mt-1.5" value={qv}
                onChange={(e) => setQv(Number(e.target.value))}
              />
            </label>
          )}
        </div>
      )}

      <Button
        variant="primary"
        onClick={() => void start()}
        disabled={busy || !input || !outputDir}
      >
        {busy ? "提交中…" : "开始压缩"}
      </Button>

      <div className="mt-6">
        <JobList />
      </div>
    </>
  );
}
```
